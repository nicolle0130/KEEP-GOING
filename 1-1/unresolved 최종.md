# 미해결 이슈 기록서 — 산책 서기

## 1. 주관적 체감 표현과 객관적 관찰 사실의 경계 분리
- **시도한 프롬프트:**
  보호자의 주관적 추측이나 감각 표현은 객관적 관찰 사실과 구분하여 적고, 의학적 판단처럼 단정하지 말 것.
- **막힌 이유:**
  구어체 메모에 `"기도가 좁아진 느낌이라 개모차에 태웠고"`처럼 보호자의 체감 묘사와 행동 조치가 한 문장에 붙어 나올 때, 이를 객관적 관찰 사실과 주관적 인상으로 기계적으로 깔끔히 분리하는 규칙이 문맥에 따라 흔들릴 여지가 있다. 원문을 과도하게 축약하면 실제 개모차 탑승이라는 사실이 흐려지고, 그대로 두면 주관적 표현이 관찰 사실처럼 읽힐 수 있다.
- **향후 대안:**
  사실 기록과 보호자 체감 표현을 분리하되 원문 표현을 인용 형태로 병기하는 방식을 별도 실험으로 검증할 예정이다.

## 2. 대화형 UI 하단 후속 제안 문구 제어
- **시도한 프롬프트:**
  정보가 충분할 때는 인사말이나 산책 조언, 다음 행동을 묻는 부가 질문이나 권유 문장을 절대 덧붙이지 말고 지정된 3개 항목만 출력할 것.
- **막힌 이유:**
  모델 본문 출력은 프롬프트 규칙대로 3개 항목으로 끝나더라도, 웹 대화형 인터페이스(UI) 차원에서 사용자 후속 대화를 유도하기 위해 화면 하단에 추천 질문이나 후속 제안 문구/버튼이 자동으로 노출되는 경우가 있다. 이는 프롬프트 텍스트만으로는 완전히 통제할 수 없는 인터페이스/시스템 영역의 한계다.
- **향후 대안:**
  향후 API 연동 환경으로 전환할 경우 응답 텍스트를 파싱해 3단 포맷 본문만 추출하는 출력 후처리 필터를 적용해 UI 차원의 부가 제안을 배제할 계획이다.
